## 去掉 rm-img OSS 依赖，资源全部本地化

**背景**：项目此前把部件图标、星球背景、乐器采样托管在阿里云 OSS
（`rm-img.oss-accelerate.aliyuncs.com`），需去掉该运行时外部依赖。

**做法**：
- 新增 `scripts/download-oss-assets.mjs`：按各组件模板的 URL 拼接规则枚举出全部
  文件（图标 111 png + 6 jpg 背景 + 71 mp3 采样 = 188 个，4.95 MB），
  并发下载到 `public/`，保持 `img/`、`instruments/` 目录结构不变。
- 新增 `scripts/verify-local-assets.mjs`：**从源码数据表独立重新推导**期望文件名
  （amp.ts / moa.ts / kitgun.ts / zaw.ts 的 name 字段），再与实际文件比对，
  用于防止模板拼接规则（camelCase、去空格、`II`→`2`）写错。
- 引用改为公共根路径 `/img/...`、`/instruments/...`，与项目既有写法一致
  （app.less / ErrorPage / Intro / Palette 本来就用 `/img/`）。
- `vite.config.ts` 删除 rm-img 的 PWA runtimeCaching 规则。

**改动文件**：AmpBuilder.vue、MoaBuilder.vue、KitgunBuilder.vue、ZawBuilder.vue、
MiniClock.vue、less/alert.less、views/music/MusicEdit.vue、vite.config.ts。

**结果**：type-check 通过；build 通过（PWA precache 189 项 5.8 MB）；
dist 内含 198 个本地资源文件，全局 `rm-img` 零残留；dev server 实测资源 200。

## 两个值得记住的坑

1. **构建通过 ≠ 路径正确**。中途 4 处模板里残留了未定义的 `${base}` 变量，
   `bun run build` 照样成功（Vite 不校验模板表达式），但运行时图片会全挂成
   `undefinedimg/...`。这类改动必须用 grep 复查 + 实跑资源 URL。
2. **本机 shell 的 sed 无法匹配含 `${...}` 的模式**（`${base}`、`\${base}`、
   `[$]{base}` 变体全部不生效，而单独 `img` 可以）。怀疑是 Bash 包装层对 `${}`
   做了处理。**规避办法：批量文本替换改用 Python 脚本**（`io.open(..., newline="")`
   保持换行），不要跟 sed 较劲。

3. **prettier 只对本来就格式化的文件跑**。MiniClock.vue 历史上没走 prettier，
   直接 `prettier --write` 会引入 95 行无关 churn。对这类文件应手工改单行，
   不跑格式化。
